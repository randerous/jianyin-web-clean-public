# 搜索临时队列长暂停恢复设计

## 问题

搜索结果播放时会形成临时队列。FLAC 地址包含短期签名；页面或 Android WebView 长时间进入后台后，队列仍会持久化，但暂停时间只存在 React 内存中。页面重载后，旧签名会被当作已验证地址继续使用。恢复流程又先等待异步解析，再调用 `audio.play()`，严格的浏览器会认为用户手势已经结束并拒绝播放。

## 修复

- 页面进入隐藏状态时，为当前远程 FLAC 歌曲记录失活时间。
- 新会话中如果当前歌曲没有本次会话的成功播放记录，第一次恢复时强制刷新 FLAC 签名。
- 用户点击恢复时，在事件处理同步阶段先尝试激活当前 audio 元素，再执行异步刷新；刷新成功后替换地址并从现有进度继续。
- 不缓存整页音频，也不改变歌单或下载语义。

## 验证

- 新增带严格用户手势门禁的 reload 回归用例：持久化旧签名临时队列，reload 后第一次点击播放即刷新为新签名并开始播放。
- 保留现有同页面长暂停、签名过期、断点续播、连续切歌测试。
- 运行生产构建、全部 API/E2E/性能门禁；Android 共用同一 React 播放链路，不运行 instrumentation。
