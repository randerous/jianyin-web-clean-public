# Jianyin Web Clean Test Plan

**Goal:** Verify the fresh web port's basic music-player workflows, with hard gates against unplayable songs and 30-second trial playback.

**Scope:** `/Users/chenguotao/jianyin-web-clean` only. Do not use or modify `/Users/chenguotao/jianyin-web`.

**Success Criteria:**
- Local seed songs, imported local songs, and accepted Netease songs can actually play in the browser.
- Any Netease song shown/imported by the app is server-verified with a URL, no `freeTrialInfo`, and `durationMs > 60000`.
- Audio playback checks use the real `<audio>` element: `paused === false`, `currentTime > 0`, and `duration > 60`.
- Core flows pass on a clean browser context: home, search, player, playlists, local import, backup/restore, and Netease import.

## P0 API And Stream Cases

### API-01 Search Filters No URL, Trial, And Too Short Songs

**Precondition:** Mock `NeteaseCloudMusicApi.search` and `song_url`.

**Steps:**
1. Make search return four candidates.
2. Make `song_url` return:
   - valid URL with `time: 65000`
   - no URL
   - `freeTrialInfo`
   - valid URL with `time: 30000`
3. Request `/api/netease/search?keyword=test&limit=20`.

**Expected:**
- Response `200`.
- Only the valid song is in `songs`.
- Returned song has `url: /api/netease/stream/:id`, `verifiedPlayable: true`, and `durationMs > 60000`.
- Bad songs never reach the frontend.

**Automation:** Add API integration test with mocked Netease module.

### API-02 Song Resolve Rejects Invalid Playback Data

**Precondition:** Mock `song_url` variants.

**Steps:**
1. Request `/api/netease/song/:id` for no URL.
2. Request `/api/netease/song/:id` for trial.
3. Request `/api/netease/song/:id` for 30s.

**Expected:**
- Each returns `404`.
- Reasons are `no_url`, `trial_fragment`, and `too_short`.
- Valid song returns stream proxy URL and `durationMs > 60000`.

**Automation:** Add API integration test.

### API-03 Stream Revalidates And Supports Range

**Precondition:** Mock `song_url` as valid and mock upstream audio fetch.

**Steps:**
1. Request `/api/netease/stream/:id` without Range.
2. Request `/api/netease/stream/:id` with `Range: bytes=0-1023`.
3. Request stream for no URL/trial/30s data.

**Expected:**
- Valid stream proxies upstream status, content headers, and body.
- Range request forwards the `Range` header upstream and preserves `206`/`content-range`.
- Invalid playback data returns `404` before upstream fetch.

**Automation:** Add API integration test.

## Current Coverage Gaps

- No API-level test directly mocks Netease playback metadata to prove no URL, trial, and 30s songs are rejected by `server.mjs`.
- No automated Range streaming test.
- No E2E test for player controls: pause/resume, seek, next/previous, and mode switching.
- Local import test should also play after reload, not only verify the row persists.
- No E2E error test for a failed Netease playlist import.
- Live Netease smoke exists as manual verification, but should be an opt-in command to prevent regressions in the exact issue the user flagged.
