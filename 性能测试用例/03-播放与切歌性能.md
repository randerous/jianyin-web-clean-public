# 03 播放与切歌性能

## 目标

验证点击播放、切下一首、上一首、暂停恢复、签名刷新时的响应时间。

## 测试方法

记录：

- `play_to_progress_ms`：点击播放到 `audio.currentTime > 0`。
- `next_to_progress_ms`：点击下一首到新歌进度增长。
- `resume_ms`：暂停后恢复到进度增长。
- `refresh_recover_ms`：链接过期后刷新恢复播放。

## 用例

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| PERF-PLAY-01 | 首页播放 | 点击首页歌曲 | `< 2s` 进度增长 |
| PERF-PLAY-02 | 歌单播放 | 歌单详情点击歌曲 | `< 2s` 进度增长 |
| PERF-PLAY-03 | 下一首 | 多首队列点击下一首 | `< 2s` 新歌进度增长 |
| PERF-PLAY-04 | 上一首 | 多首队列点击上一首 | `< 2s` 新歌进度增长 |
| PERF-PLAY-05 | 暂停恢复 | 暂停 5s 后恢复 | `< 1s` 恢复 |
| PERF-PLAY-06 | FLAC 过期恢复 | mock stream 失败后刷新 | `< 3s` 恢复且进度接近 |
| PERF-PLAY-07 | 连续切歌 | 连点下一首 10 次 | 无 UI 卡死，最终可播放 |

## 记录字段

```text
song_source:
queue_size:
play_to_progress_ms:
next_to_progress_ms:
resume_ms:
recover_ms:
failed_attempts:
```

## 通过标准

- 播放和切歌 P95 `< 3s`。
- 连续切歌不造成队列错乱。
- 失败恢复必须有明确 toast 或自动恢复成功。
