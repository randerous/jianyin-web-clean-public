# 05 数据恢复与存储性能

## 目标

验证大状态恢复、localStorage 合并、IndexedDB orphan 音频重新挂载的耗时。

## 测试数据

建议隔离构造：

- 歌单：10 个。
- 每个歌单：100 首。
- 下载记录：57、200 两档。
- orphan 下载：downloadHistory 有记录但 `localKey` 缺失，IDB blob 存在。

## 用例

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| PERF-DATA-01 | 普通状态启动 | 100 首本地状态启动 | 我的页 `< 1s` |
| PERF-DATA-02 | 大歌单状态 | 1000 首状态启动 | 首屏 `< 2s`，无白屏 |
| PERF-DATA-03 | 空共享保护 | 本地大状态 + 空共享 | 不覆盖，合并 `< 1s` |
| PERF-DATA-04 | orphan 恢复 57 条 | IDB 有 57 blobs | `< 2s` 全部挂回 |
| PERF-DATA-05 | orphan 恢复 200 条 | IDB 有 200 blobs | `< 5s` 完成，无卡死 |
| PERF-DATA-06 | 备份恢复 | 导入含本地音频备份 | 有进度反馈，不白屏 |

## 记录字段

```text
playlist_count:
song_count:
download_history_count:
idb_blob_count:
hydrate_ms:
local_storage_size_kb:
orphan_reattached_count:
```

## 通过标准

- 57 条真实恢复规模下，启动后下载项应全部为 `local-file:download_...`。
- 大状态不应阻塞页面超过 5 秒。
