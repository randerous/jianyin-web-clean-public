# 06 UI 渲染与交互响应性能

## 目标

验证长列表、弹窗、toast、移动端布局在大量数据下是否卡顿或遮挡。

## 测试方法

使用 Playwright 或 Chrome Performance：

- 记录点击到 UI 变化耗时。
- 记录 long task 数量。
- 观察滚动帧率和输入延迟。

## 用例

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| PERF-UI-01 | 我的页 1000 首 | mock 大歌单后打开我的页 | `< 1.5s` 可交互 |
| PERF-UI-02 | 歌单详情 1000 首 | 打开大歌单详情 | `< 2s` 首屏可见 |
| PERF-UI-03 | 歌单内搜索 | 大歌单内输入关键词 | `< 500ms` 更新结果 |
| PERF-UI-04 | 滚动 | 大歌单连续滚动 | 无明显卡顿 |
| PERF-UI-05 | toast 层级 | 播放 + toast + 移动端 | toast 不遮挡关键按钮 |
| PERF-UI-06 | 设置弹窗 | 播放时打开设置 | `< 500ms` 弹窗可操作 |
| PERF-UI-07 | 账号弹窗错误 | mock 错误后显示 | `< 1s` 错误可见 |

## 记录字段

```text
viewport:
list_size:
open_ms:
filter_ms:
long_task_count:
max_long_task_ms:
visual_overlap:
```

## 通过标准

- 常规点击到 UI 响应 P95 `< 500ms`。
- 大列表打开 P95 `< 2s`。
- 不出现播放器/导航/toast/弹窗互相遮挡。
