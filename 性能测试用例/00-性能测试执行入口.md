# 00 性能测试执行入口

## 目标

建立统一性能测试流程，避免不同模型用不同口径测试。

## 环境准备

```bash
cd /Volumes/Ventoy/tools/jianyin-web-clean-public
npm run test:perf
```

Playwright 自动启动 `5190` 隔离服务，状态文件为 `test-results/.jianyin-performance-state.json`，单 worker 串行执行。
`npm run test:perf` 会先执行生产构建，再用 `dev: false` 服务测试 `dist`；不会使用 Vite 开发模式数据冒充发布性能。

## 推荐执行顺序

| 顺序 | 文件 | 目的 |
|---|---|---|
| 1 | `01-首页与歌单加载性能.md` | 找推荐歌单/首页首屏慢点 |
| 2 | `02-搜索性能.md` | 找搜索请求、竞态、渲染慢点 |
| 3 | `03-播放与切歌性能.md` | 找播放首帧、下一首慢点 |
| 4 | `04-下载与本地缓存性能.md` | 找下载缓存、本地播放慢点 |
| 5 | `05-数据恢复与存储性能.md` | 找 localStorage/IndexedDB 恢复慢点 |
| 6 | `06-UI渲染与交互响应性能.md` | 找长列表、弹窗、滚动卡顿 |
| 7 | `07-APK真机性能.md` | 真机冷启动、播放、切歌、页面切换 |

## 通用通过标准

| 指标 | 桌面端目标 | 真机目标 |
|---|---:|---:|
| 首页首屏可见 | `< 2s` | `< 3s` |
| 推荐歌单详情首屏 | `< 3s` | `< 4s` |
| 搜索出首个结果 | `< 3s` | `< 4s` |
| 点击播放到出声/进度增长 | `< 2s` | `< 3s` |
| 下一首切换到进度增长 | `< 2s` | `< 3s` |
| 我的页打开 | `< 1s` | `< 1.5s` |
| 长任务 | 无连续卡死 | 无明显卡死 |

统计规则：

- P50/P95 指标至少采样 5 次，并使用 nearest-rank 计算。
- 单次故障注入或容量 smoke 只报告 `single-run-smoke` 和实际值，不冒充 P50/P95。
- 计时前必须等待页面达到可交互稳态；禁止用固定 sleep 作为完成事件。
- 功能 E2E 与性能 E2E 不得同时共享后端状态文件。
